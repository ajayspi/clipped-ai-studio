1. **Credential map for xbneet:** publishable key (anon, browser) `sb_publishable_…`, secret key (service role, **Kong blocks it for browser UAs** — PowerShell gets "Forbidden use of secret API key in browser"; supabase-js UA is fine), legacy **anon + service_role JWTs** (used in `.env.local` — zero UA restrictions), and the account **PAT `sbp_…`** (only thing that runs `POST /v1/projects/{ref}/database/query`).
2. **Management API quirk:** `POST /database/query` returns **201 with an empty `[]` body for successful DDL** (no rows). A first applier treated 201 as failure — all 6 chunks had in fact executed. Success = `200` or `201`.
3. **ddl composite (6 chunks):** drop legacy `videos/settings/render_jobs/scheduled_posts` → `schema.sql` (7 tables, no RLS) → 3 tracked migrations → grants. **`GRANT EXECUTE ON ALL FUNCTIONS` is required** — PostgREST 404s RPCs the calling role can't execute, indistinguishable from missing functions. (Also: a `{}`-bodied REST probe 404s functions with required args — the earlier "404 MISSING" was the probe, not the DB; a real call with args returns 200.)
4. **Claims 42702 — real SQL bug found in `20260905_render_job_leases.sql`:** `claim_render_job` declared `RETURNS TABLE (id, orchestration_state, lease_token)`; the **out-param `orchestration_state` shadows the same-named column** → `ERROR 42702: column reference "orchestration_state" is ambiguous` on every claim. `fail_render_job` has no such OUT param, hence worked. Fixed by qualifying every column ref with `render_jobs.` (comment added in-file). Verified cycle: seed queued → claim (1 row) → second claim (empty) → `complete_render_job` with **60s** lease → `true` (a **1s** lease legitimately expires before the next call — `false` is correct there, not a bug) → row `completed` + `output_url`.
