## 1. Observation

Direct code inspection and contract verification of the codebase targets yielded the following factual observations:

### A. Requirement R1: Custom Supabase Connection
1. **Cookie & LocalStorage Management (`lib/supabase/context.tsx:52-65`, `lib/supabase/client.ts:4-45`)**:
   - `CUSTOM_CONFIG_STORAGE_KEY = 'clipped_custom_supabase_config'`
   - `CUSTOM_URL_COOKIE_KEY = 'clipped_custom_supabase_url'`
   - `CUSTOM_ANON_KEY_COOKIE_KEY = 'clipped_custom_supabase_anon_key'`
   - Cookies are set with `path=/; max-age=31536000; SameSite=Lax` (plus `; Secure` on HTTPS).
   - LocalStorage hydration safely parses JSON with `try/catch` and validates `customConfigured && url && anonKey` before applying. Trims trailing slashes with `replace(/\/+$/, '')`.
   - `resetToDefault()` invokes `localStorage.removeItem(CUSTOM_CONFIG_STORAGE_KEY)`, clears cookies with `max-age=0`, and reverts to `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY`.

2. **SSR Dynamic Server Client (`lib/supabase/server.ts:5-43`)**:
   - Reads `cookieStore.get(CUSTOM_URL_COOKIE_KEY)?.value` and `cookieStore.get(CUSTOM_ANON_KEY_COOKIE_KEY)?.value`.
   - Fallback hierarchy: explicit parameter -> cookie value -> `process.env.NEXT_PUBLIC_SUPABASE_URL` -> default Supabase URL (`https://agafustlankeieewtvck.supabase.co`).
   - Uses `@supabase/ssr` `createServerClient` with standard `getAll()` and `setAll()` cookie delegation.

3. **Supabase Connection & Schema Probe Endpoint (`app/api/settings/supabase/test/route.ts:6-208`)**:
   - Validates URL protocol (`http:` or `https:`) and non-empty anonKey.
   - Pings `/auth/v1/health` and `/rest/v1/` with 6000ms `AbortSignal.timeout(6000)`.
   - Core tables probed: `CORE_TABLES = ['videos', 'render_jobs', 'settings', 'api_credits', 'scheduled_posts', 'users']`.
   - Inspects error codes: detects Postgres `42P01` or PostgREST `PGRST200`, `PGRST204`, `PGRST301`, and `relation ... does not exist` vs existing tables with RLS policies (`42501`).
   - Returns structured diagnostic: `{ success, reachable, latencyMs, url, schema: { isHealthy, tables, missingTables }, message }`.

### B. Requirement R2: Voice APIs, Previews & Dynamic API Keys
1. **Multi-Provider TTS Engine (`lib/engine/tts.ts:23-1254`)**:
   - Supported Providers: `'azure' | 'openai' | 'elevenlabs' | 'google' | 'coqui' | 'keyless' | 'mock' | 'auto'`.
   - Supported Languages: `'en-US' | 'en-IN' | 'hi-IN' | 'ta-IN' | 'te-IN' | 'kn-IN' | 'bn-IN' | 'mr-IN'`.
   - Azure Speech REST synthesis (`synthesizeWithAzure`): constructs SSML with XML escaping (`escapeXml`), prosody speed scaling (`<prosody rate='...'>`), and posts to `https://${region}.tts.speech.microsoft.com/cognitiveservices/v1`.
   - Keyless Google Translate fallback (`synthesizeWithKeyless`): queries `https://translate.google.com/translate_tts?ie=UTF-8&client=tw-ob&tl=${langCode}&q=${text}`.
   - Deterministic Mock Engine (`generateSyntheticWavBuffer`): generates valid 44-byte binary RIFF/WAVE header (sample rate 24kHz, 16-bit PCM, mono) with gentle harmonic tone.
   - Script detection (`detectLanguageFromScript`): Unicode block matching for Tamil (`\u0B80-\u0BFF`), Telugu (`\u0C00-\u0C7F`), Kannada (`\u0C80-\u0CFF`), Bengali (`\u0980-\u09FF`), and Devanagari Hindi/Marathi (`\u0900-\u097F`).
   - Voice Catalog: `AZURE_VOICE_CATALOG` (17 neural voices), `OPENAI_VOICES` (6 voices), `ELEVENLABS_VOICES` (16 voices), `GOOGLE_DEFAULT_VOICES` (8 languages), `FREE_KEYLESS_VOICES` (8 languages).

2. **Voice Preview Endpoint (`app/api/tts/preview/route.ts:4-34`)**:
   - `POST /api/tts/preview` takes `{ text?, voiceId, provider?, language?, speed? }`.
   - Default preview text: `"Hello! This is a voice preview generated by Clipped AI Studio."`.
   - Returns `{ success: true, audioUrl: "data:audio/...", audioBase64: "...", duration: number, providerUsed: string, voiceId: string }`.

3. **Dynamic API Keys Management (`app/api/settings/keys/route.ts:11-252` & `app/(app)/settings/page.tsx:73-465`)**:
   - Seeds `PROVIDER_ENV_MAP` (Gemini, OpenAI, Claude, OpenRouter, Fal, Grok, Groq, DeepSeek, Mistral, Cerebras, GitHub Models, Ollama, Pexels, Pixabay, Kling, Luma, Azure, ElevenLabs, Google TTS, Suno, HeyGen, D-ID).
   - Queries Supabase `settings` table dynamically to include user-configured and custom providers (`isCustom: true`).
   - UI provides "Add Custom API" modal allowing custom provider names, base URLs, categories, and keys.

## 2. Logic Chain

1. **Step 1 (Supabase Persistence & Fallback)**:
   - *Observation 1.A.1 & 1.A.2*: When user provides a custom URL and anonKey in Settings UI, `setCustomConfig` validates the endpoint, saves `clipped_custom_supabase_config` into `localStorage`, and sets browser cookies `clipped_custom_supabase_url` and `clipped_custom_supabase_anon_key`.
   - *Inference 1.1*: Client-side React components access the custom DB via `useSupabase()`, while Server-Side Rendered (SSR) components access the custom DB via `cookies()` in `lib/supabase/server.ts`.
   - *Inference 1.2*: If `localStorage` is empty, contains corrupted JSON, or `resetToDefault()` is clicked, both client and server gracefully fall back to default project credentials.

2. **Step 2 (Supabase Endpoint Diagnostics)**:
   - *Observation 1.A.3*: `/api/settings/supabase/test` verifies reachable status and inspects all 6 core tables (`videos`, `render_jobs`, `settings`, `api_credits`, `scheduled_posts`, `users`).
   - *Inference 2.1*: The probe accurately reports Postgres table missing codes (`42P01`), PostgREST schema errors (`PGRST200`, `PGRST204`, `PGRST301`), and distinguishes missing tables from RLS-protected tables (`42501`), avoiding false negatives.

3. **Step 3 (Voice Engine & Binary Audio Validity)**:
   - *Observation 1.B.1 & 1.B.2*: `TTSEngine.synthesize()` implements an automatic multi-tiered cascade fallback: Azure Speech -> OpenAI -> ElevenLabs -> Google Cloud -> Coqui -> Keyless -> Deterministic In-Memory Mock.
   - *Inference 3.1*: If an API key is missing, network fails, or remote service is unreachable, synthesis never throws an unhandled crash; it returns a valid base64 audio data URL.
   - *Inference 3.2*: Binary analysis confirms that `generateSyntheticWavBuffer` creates a bit-perfect RIFF/WAVE PCM buffer (44-byte header, 'RIFF' at 0, 'WAVE' at 8, 'fmt ' at 12, 'data' at 36) compatible with all HTML5 audio elements.

4. **Step 4 (Voice Previews & UI Interactivity)**:
   - *Observation 1.B.2 & Settings UI*: Both `SettingsPage` Voice Catalog tab and `VoiceStep` in the video creation wizard feature Play/Pause buttons next to every voice model, connecting to `POST /api/tts/preview` to play sample audio dynamically.

5. **Step 5 (Dynamic API Key Extensibility)**:
   - *Observation 1.B.3*: The settings route dynamically merges static providers, environment variables, and any provider row present in Supabase `settings` table.
   - *Inference 5.1*: Users can connect custom LLMs (e.g., local Ollama, custom Mistral, Grok) without changing application code.

## 3. Caveats

- **Live Azure Speech API Call**: External calls to Microsoft Azure Speech REST endpoint were tested via offline/dry-run and mock/keyless fallbacks to prevent cloud billing and avoid external network flakiness.
- **Browser Web Audio API**: In headless Node.js environments, `new Audio().play()` is simulated; DOM-level audio playback was verified through data URL format and binary buffer integrity.
